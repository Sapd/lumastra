# P01 checkpoint evidence — 2026-10-17

The P01 contract implementation is complete. Shared foundation/image gates remain
separate. This evidence does not authorize traffic selection, rollout, or a claim
that the Rust proxy streams live media.

## Native contract checks

Remote slots: `proxy-rust` (baseline/full lint), `proxy-rust-probe` (final P01
increment); independent locked Cargo crate, pinned Rust 1.99.1.

- Ten Rust tests, format, strict clippy (`-D warnings`), and locked debug build pass.
- The shared `scripts/native.mjs` release build, dependency-license capture and
  `--version` smoke pass. All 25 conformance groups also pass using the optimized
  `build/lumastra-livetv-proxy` executable. This is Linux amd64 runner evidence;
  multiarchitecture container smoke remains a shared foundation/rollout gate.
- The full TypeScript reference suite passes: 43 files / 613 tests, including real
  FFmpeg serving/failover/compat/HDR/feed checks.
- Twenty-five differential test groups in seven files pass. Expected results are evaluated
  by live TypeScript reference functions; the Rust executable is required.
- Actual loopback HTTP checks cover auth/health/shutdown precedence, malformed
  routes/containers, ordered join validation, 64 KiB body limits, and 28 ready-media
  URLs (playlists/masters/init generations/binary segments/cache headers).
- Actual HTTP warm-playlist checks return after one fixture entry becomes ready
  at 600 ms (763 ms observed test duration). Empty and mid-failover requests retain
  the 18-second deadline; disconnecting a request releases the native waiter and
  stops TypeScript reference polling. These tests do not create media segments.
- Real child-process tests prove shared HDR probe ownership, success/empty-result
  caching, exact 60-second failure retry, cancellation isolation, bounded output
  and runtime, and child reaping on timeout and shutdown. The filter-policy matrix
  also compares seven stdout cases across four GPU modes and two platforms with
  the TypeScript probe using a fixture executable. No GPU encode is demonstrated.
- The HTTP managers are fixtures. Valid join results are fixture replies. No real
  ingest, upstream connection, encoder admission, or feed lifecycle is demonstrated.
- Raw ffprobe parsing compares against a real fixture executable's stdout, not a
  provider probe. fMP4 timing/chunk/reset checks use generated binary fixtures.
- Scoped TypeScript typecheck and ESLint pass. License metadata was captured for
  73 native packages; repository SPDX and license-boundary checks pass.
- Coordinated full `npm run lint` passed on the baseline checkpoint, including
  the frozen watcher/runtime sources. The final playlist/filter increment passed
  scoped ESLint/typecheck and SPDX checks; it did not repeat that global lint.
- One bounded independent review of parser/HTTP/auth/status boundaries found no
  concrete high-value defect. This was not the P02 independent security gate.

The exact pure cross-products include GPU/transcode decisions, ordered ingress,
fixed/remux/adaptive FFmpeg argv, HDR hardware cooldown/reservation, codec metadata,
master/media HLS rendering and status withholding. The tests preserve JS whitespace,
UTF-8 secret comparison plus HTTP/1 Latin-1 header decoding, and decimal half
rounding for `EXTINF` durations.

## TypeScript continuous-feed cadence reference

The existing real-FFmpeg/network cadence check ran as part of the unchanged
TypeScript proxy reference suite. It used a synthetic 320x180 source, actual HTTP,
ingest FFmpeg, the continuous MPEG-TS feed and an actual fixed-rung FFmpeg process.
The measurements describe complete segment availability, not decoded timestamps.

| Measurement (milliseconds)           |  p50 |  p90 |  max |
| ------------------------------------ | ---: | ---: | ---: |
| Ingest arrival gap                   | 2075 | 4152 | 4226 |
| Rung arrival gap                     | 2070 | 4172 | 4236 |
| Rung arrival age since latest ingest |  130 |  146 |  146 |

Observation: 30,003 ms; 10 ingest and 10 rung segments; at most one newly observed
rung per poll. Natural source GOP/segment cadence included roughly four-second
gaps, so those gaps are not evidence of renewed polling delay. The relevant result
is the matching ingest/rung cadence and small additional delay, without a batched
rung release.

Arrival offsets from observation start, milliseconds:

- Ingest: `3592,5479,9705,11593,15517,17592,21563,23553,27705,29592`
- Rung: `3699,5581,9817,11695,15625,17695,21673,23656,27828,29694`

This is a TypeScript reference measurement. P03 must repeat the actual HTTP/FFmpeg
harness through the native lifecycle implementation. No provider/device playback
or long soak was performed. The earlier corrected old-HLS negative control showed
extra delay but did not reproduce the reported production x2/x3 bursts; it is not
an end-to-end reproduction of that incident.
